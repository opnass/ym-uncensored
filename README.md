# YM Uncensored

Браузерное расширение (Chrome/Edge, Manifest V3), которое подменяет зацензуренные
треки в веб-плеере Яндекс.Музыки на твои локальные explicit-версии.

Работает в «Моей волне», плейлистах, поиске и на страницах альбомов.
Плеер Яндекса не держит медиаэлемент в DOM (см. «Как это устроено»), поэтому
элемент ловится в момент создания, а не поиском по документу. Лайки, дизлайки и история остаются
привязанными к оригинальному треку: подмена идёт на уровне источника аудио,
а не подменой объекта трека.

## Установка

1. Распакуй архив.
2. Открой `chrome://extensions` → включи «Режим разработчика».
3. «Загрузить распакованное расширение» → выбери папку `extension`.
4. Открой `music.yandex.ru`, обнови вкладку.

## Как пользоваться

1. Иконка расширения → «Библиотека и настройки».
2. Перетащи аудиофайлы в зону импорта. Имя вида `Исполнитель - Название.mp3`
   сильно улучшает автоматч — из него берутся артист и титул.
3. Режим по умолчанию — «Всегда давать грязную версию»: если для играющего трека
   находится файл, плеер сразу играет его, позиция и громкость сохраняются.
4. Автоматч ошибся → открой попап на нужном треке, выбери файл вручную и нажми
   «Привязать к текущему треку». Ручная привязка приоритетнее авто.
5. `✕` в попапе разрывает привязку.

## Статус прямо на странице

В левом нижнем углу плеера висит плашка `YMU` — она показывает, что происходит
прямо сейчас, без открытия попапа и консоли:

```
YMU «МУККА — Таблетка» · ищу файл
YMU файл найден, загружаю
YMU играет локальная версия (файл готов)
YMU мукка|таблетка · лучший 0.65 < порога 0.82
YMU трек не определён — включи воспроизведение
```

Плашку можно отключить в настройках (`badge`).

## Как это устроено

### Почему нельзя просто подменить `src`

Захват трафика показал, как Яндекс отдаёт звук:

```
get-file-info → downloadInfo: {
  codec: "aac-mp4", bitrate: 192,
  transport: "encraw",                    ← поток зашифрован
  key: "a258c71e…",                       ← ключ для расшифровки
  urls: ["…/music-v2/crypt/ysign1=…"]
}
```

Плеер скачивает зашифрованные байты, расшифровывает их в JS и ставит медиаэлементу
**свой собственный `blob:`**. Если в этот момент подменить `src`, начинается гонка:
плеер ставит свой blob, расширение — свой, плеер снова свой. Элемент не доходит
до готовности, трек не запускается. Именно это ломало воспроизведение в 0.5.0.

### Параллельное воспроизведение

Поэтому элемент плеера **не трогается вообще**:

1. Элемент плеера ловится реестром (`createElement` / `new Audio()` / `play()`) —
   в DOM его нет, `querySelector('audio')` возвращает `null`.
2. Если для трека есть локальный файл, плеер **глушится** (`muted = true`),
   а расширение играет копию в **своём** элементе.
3. Раз в 400 мс копия синхронизируется с плеером: пауза, позиция (допуск 0.4 с),
   громкость, скорость.
4. Плеер продолжает работать как обычно: прогресс-бар, лайки, переключение треков,
   «Моя волна» — всё на его стороне.

```
плеер Яндекса (не трогаем)          расширение
──────────────────────────          ──────────────────────
зашифрованный поток                 IndexedDB → чанки base64
  → расшифровка в JS                  → Blob → blob: URL
  → свой blob: → <audio>              → свой <audio>
        │ muted = true                       ▲
        │ paused / currentTime / volume ─────┘ синхронизация 400 мс
```

### Аварийный откат

Если локальный файл не годится — плеер **разглушается** и играет оригинал:

| Ситуация | Что видно на плашке | Что происходит |
|---|---|---|
| Формат не поддерживается браузером | `локальный файл отклонён: формат…` | плеер не глушится вовсе |
| Файл не декодируется (`MediaError`) | `локальный файл отклонён: файл не декодируется` | привязка отключается |
| `play()` отклонён | `не удалось запустить копию…` | копия останавливается |
| Нет файла / выключено | ключ и причина | плеер играет как обычно |

Главное правило: **расширение не может оставить тебя без звука**. Любой сбой
копии возвращает звук плеера.

### Слои

- **inject.js** (MAIN world) — реестр элементов, определение трека, параллельная копия.
- **bridge.js** (ISOLATED) — только транспорт; неизвестные типы пересылаются прозрачно.
- **background.js** (service worker) — библиотека в IndexedDB, нормализация, автоматч.

Нормализация живёт только в service worker; страница присылает сырые
`title`/`artists` и получает `{ ok, key, fileId, enabled, reason }`.

## Определение трека

Три пути, в порядке надёжности:

1. `navigator.mediaSession.metadata` — основной.
2. Ссылка `a[href*="/track/"]` в баре плеера.
3. `document.title` вида «Трек — Исполнитель — Яндекс.Музыка».

Если ни один не сработал, плашка честно скажет «трек не определён».

## Автоматч

Точное совпадение ключа → берётся файл с ближайшей длительностью.
Иначе — скоринг `0.62·Дайс(титул) + 0.38·Дайс(артисты)` плюс поправка за
длительность: до `+0.08` при ±3 с, до `−0.35` при разнице больше 40 с.
Порог по умолчанию `0.82`, регулируется ползунком.

Из названий выкидываются `(Explicit)`, `(Remastered)`, `[Explicit Version]`,
`feat. …`, `ё→е`, пунктуация — поэтому «Таблетка» и «Таблетка (Explicit Version)»
дают один ключ. Значимые скобки вроде `(prod. by X)` или `[Bonus Track]`
сохраняются: это разные версии, их нельзя схлопывать.

## Отладка

- Плашка на странице — первый источник правды.
- Попап: панель «Диагностика — где рвётся», этапы идут по порядку
  `трек определён → матч найден → файл собран → подмена применена`.
- Консоль страницы: сообщения `[YMU]`.
- Service worker: `chrome://extensions` → «Проверять вид service worker».
- Режим захвата трафика в настройках пишет образцы JSON-ответов и аудио-URL.

## Тесты

```bash
node test/unit.js         # нормализация, ключи, скоринг, имена файлов
node test/integration.js  # inject + bridge + SW, соединённые как в браузере
```

Интеграционный тест — регрессия на баг 0.2.0: страница **без** `window.YMU`
обязана определить трек. Если кто-то снова свяжет страницу с нормализацией,
тест упадёт первым.

## Ограничения

- Только браузер на `music.yandex.ru`. Десктопное приложение — Electron, другая история.
- Explicit-версии в сети расширение не ищет: подставляет только твои файлы.
- **Длительность.** Если локальный файл длиннее или короче оригинала, синхронизация
  идёт по позиции плеера. Когда оригинал кончится, плеер переключит трек —
  хвост длинной версии обрежется. Для «Таблетки»: оригинал 2:46, твой файл 2:55.
- **Перемотка** работает через ползунок плеера: копия подтягивается к его позиции.
- **Эквалайзер и нормализация громкости** Яндекса к копии не применяются.
- Определение трека опирается на Media Session и DOM — при редизайне плеера
  может понадобиться правка `fromDom` в `inject.js`.

## История версий

**0.6.0 — параллельное воспроизведение вместо подмены `src`**

Симптом: привязанные треки переставали запускаться, остальные играли.
Причина найдена в захвате: Яндекс отдаёт зашифрованный поток
(`transport: "encraw"`, `/music-v2/crypt/`) и после расшифровки ставит элементу
свой `blob:`. Перехват сеттера `src` в 0.5.0 затирал любое присвоение — включая
blob самого плеера — и вступал с ним в бесконечную гонку.

1. **Сеттер `src` и `setAttribute` больше не перехватываются.** Тест проверяет
   это по коду и по поведению: `src` плеера после работы расширения не меняется.
2. **Своя копия в отдельном элементе**, плеер глушится, синхронизация 400 мс.
3. **Аварийный откат**: неподдерживаемый формат, ошибка декодирования, отказ
   `play()` — звук плеера возвращается, битая привязка отключается.
4. **Мост пересылает неизвестные типы сообщений** прозрачно — новая функция
   в странице больше не требует правки `bridge.js`.
5. В 0.5.0 плашка писала «играет локальная версия» сразу после подмены,
   не проверяя результат. Теперь успех объявляется, только когда копия реально играет.

**0.5.0 — подмена в отсоединённый элемент**

Диагноз по консоли: `document.querySelector('audio')` → `null`, `count: 0`,
`AudioContext` не создавался, но музыка играет и громкость регулируется.
Значит элемент создан через JS и не вставлен в DOM, а весь код 0.4.0 искал его
через `querySelector` и молча выходил — файл доезжал, подставлять было некуда.

1. **Реестр медиаэлементов** вместо поиска в DOM: перехват
   `Document.prototype.createElement`, `new window.Audio()`, `play()`, плюс
   резервный `scanDom` с обходом shadowRoot.
2. **`applyAll`** подставляет источник во все активные элементы реестра,
   а не в один найденный.
3. **Возвращён захват трафика**, потерянный в 0.3.0: перехват `fetch`/`XHR`
   снова пишет образцы в IndexedDB. Кнопка «Выгрузить захват» до этого всегда
   отдавала пустой массив — это была моя регрессия.
4. **`all_frames: true`** на случай, если плеер в iframe.
5. **Честный статус**, если элемент не найден: «плеер не найден (элементов: N)».

**0.4.0 — пустой артист и залипшая передача**

Причина по логу: `трек: определён « — Таблетка»`, артист пустой.

1. **`mediaSession || DOM` съедало артиста.** После логина Яндекс заполняет
   `mediaSession`, но без `artist`; короткое замыкание не давало добрать его
   из DOM. Ключ `|таблетка` вместо `мукка|таблетка`, скор 0.62 < 0.82.
   Теперь источники дополняют друг друга.
2. **Матч по одному названию** при отсутствии артиста: порог 0.90 и отрыв 0.12
   от второго кандидата.
3. **Передача файла больше не залипает:** таймаут шага, сброс через 20 с,
   перезапрос через 12 с, повтор чанка при обрыве.
4. **Ложное «оборвалось на»**: бралась первая ошибка, а не последняя запись.
5. **Прогресс загрузки** в плашке.

**0.3.0 — регресс определения трека**

`inject.js` стал зависимым от `window.YMU` с `return` при её отсутствии —
в 0.1.0 нормализация была внутри файла. Одна «дедупликация» выключила конвейер.
Нормализация перенесена в SW; страница получает готовый ответ.
Плюс: возврат к сетевому источнику при выключении, плашка статуса,
три пути определения трека, интеграционный тест.

**0.2.0** — единая нормализация, диагностика в попапе, запасной DOM-путь.

**0.1.0** — первая сборка: библиотека, автоматч, подмена через `blob:`.

## Правовая рамка

Инструмент меняет воспроизведение локальными файлами на своей машине. Используй
свои файлы, не публикуй расширение в сторах и учитывай, что модификация клиента
может расходиться с пользовательским соглашением сервиса.
