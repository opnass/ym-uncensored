# История версий

**0.9.2 — попап без диагностики**

1. Из попапа убраны панель «Диагностика — где рвётся», кнопка «Отчёт» и ↻.
2. Отчёт, захват трафика и переключатель плашки — в свёрнутом разделе «Отладка»
   в самом низу настроек. Диагностика по-прежнему пишется в фоне — отчёт из неё собирается.

**0.9.1 — автоматч по тегам и для имён без « - »**

Симптом по отчёту: файлы вида `Мукка Таблетка.mp3` не находились — скор 0.46 при пороге 0.82
(и даже при 0.5). Имя без « - » разбиралось как одно название с пустым исполнителем,
и сравнение «исполнитель к исполнителю» давало ноль.

1. **Теги файла приоритетнее имени:** ID3v2.2–2.4 (TIT2/TPE1, в том числе CP1251 в старых
   русских mp3), ID3v1, FLAC (Vorbis comments), M4A (©nam/©ART).
2. **Уже загруженные файлы** фон перечитывает один раз при следующем сопоставлении —
   ключ обновляется, открывать настройки не нужно.
3. **Свободное сравнение** для файлов без исполнителя: строка «исполнитель название»
   целиком, в любом порядке, чуть строже обычного.
4. Из имени файла убираются метки сайтов (`(hitmo.net)`).
5. В отчёте больше нет устаревшей версии страницы.

**0.9.0 — автоимпорт только что скачанных треков**

1. **Скачал — уже в библиотеке.** Фон слушает `chrome.downloads` (новое разрешение `downloads`):
   завершилась загрузка аудиофайла — он встаёт в очередь и читается из папки, выбранной
   один раз через File System Access (поиск по имени и размеру, с подпапками до 2 уровней).
   Не-аудио игнорируется, дубликаты (то же имя и размер) не импортируются.
2. **Играющий трек включается сразу:** после импорта фон заново сопоставляет текущий трек
   и, если файл подошёл, отдаёт его странице — explicit-версия начинает играть без перезагрузки.
3. **Нет доступа к папке** (Chrome спрашивает его заново после перезапуска) — файл ждёт в очереди,
   на иконке «+N», в попапе кнопка «Импортировать» (там есть клик, и Chrome может спросить доступ).
4. **«Сканировать папку»** — импорт всех аудиофайлов папки, которых нет в библиотеке.
5. Импорт вынесен в общий `importer.js` (фон, настройки, попап); обложка в фоне рисуется
   на `OffscreenCanvas`; длительность файлов, импортированных фоном, дочитывается
   при открытии библиотеки.

**0.8.0 — где найти explicit-версию**

1. **Кнопки поиска в попапе** для текущего трека: магазины, где трек продаётся файлом.
   Основной сайт — первым и подсвечен.
2. **«Где искать» в настройках:** Bandcamp, Apple / iTunes, Qobuz включены, 7digital,
   Amazon Music, Beatport — выключены; основной выбирается; шаблон любого сайта правится;
   свой сайт добавляется шаблоном `https://…{q}…` (проверяется: только http(s) и с `{q}`).
3. **«Треки без файла»:** что играло без локальной версии, со счётчиком и кнопками поиска,
   скрытие ненужного, очистка. Записываются только треки, определённые через Media Session —
   ложные определения по DOM (ссылка со страницы, заголовок вкладки) в список не попадают.
   Импортированный трек уходит из списка сам.
4. Из запроса убираются метки сайтов (`(hitmo.net)`) и пометки цензуры (`(Clean)`, `[Radio Edit]`).

Расширение по-прежнему ничего не скачивает: ссылки ведут на страницу поиска магазина.

**0.7.4 — время вставки на ползунке, вставки при ручном переключении**

1. **Время вставки у ползунка.** По отчёту 0.7.3 у Яндекса метки времени лежат не в блоке
   с названием, а в полосе прогресса (`ChangeTimecodeBackground`) того же бара — 0.7.3 их не
   видела, и плеер показывал длину следующего трека. Теперь метки ищутся во всём баре
   плеера (внешний элемент с `PlayerBar` в классе, иначе первый предок внизу экрана с метками).
   Какая метка — длина, определяется по значению (совпадает с длиной придержанного трека),
   а не по порядку в разметке; формат как у плеера (`02:37`).
2. **Вставка при ручном переключении.** Жребий бросается в начале трека, файл заранее
   в памяти, и вставка звучит на ближайшем переходе — естественном или по кнопке «следующий»
   / выбору трека. Галочка в настройках, по умолчанию включено; выключенная галочка
   возвращает прежнее поведение (только естественный конец, жребий за 25 с).
3. Если на жребии ещё не прошёл интервал, а истечёт он посреди трека, жребий бросается
   повторно в том же треке, а не со следующего.

**0.7.3 — бар плеера ищется по тексту, время вставки на ползунке**

Симптом: ползунок работал, но время не показывалось, а название и обложка не менялись:
поиск бара по кнопкам с подписями на живом сайте не находил бар.

1. **Бар ищется по названию текущего трека**: текстовый узел с ним в нижней половине экрана,
   корень — ближайший предок с картинкой и кнопками. Название берётся из Media Session
   до подмены и из последнего определённого трека. Поиск по ссылкам остался запасным.
2. **Время вставки на ползунке:** метки вида `1:23` в баре показывают позицию и длину вставки
   (или «осталось», если плеер так показывает).
3. **MutationObserver на баре:** когда React возвращает свои значения, наши ставятся обратно
   до отрисовки — без мигания.
4. **Плашка выше бара плеера** и перетаскивается мышкой, позиция запоминается.
5. **Кнопка «📋 Отчёт» в попапе:** диагностика, настройки и устройство нижней части страницы
   (тексты, кнопки, найденный бар) — одним текстом в буфер обмена.

**0.7.2 — плеер показывает вставку**

1. **Ползунок и кнопка «пауза» отражают вставку.** На время вставки у придержанного элемента
   плеера (на самом объекте, не на прототипе и не `src`) стоят геттеры `currentTime`,
   `duration`, `paused`, `ended`: интерфейс видит позицию и паузу вставки, а перемотка
   ползунком уходит во вставку. События `timeupdate`/`seeked` пробрасываются плееру.
   После вставки геттеры снимаются, трек стартует с 0:00.
2. **Название, исполнитель и обложка вставки** в баре плеера, в системной плашке
   (Media Session) и в заголовке вкладки. Бар ищется по устройству, а не по классам:
   ссылка на трек, ближе всего к которой есть кнопки управления. Текстовые узлы React
   не пересоздаются — меняется только их значение, и после вставки всё возвращается.
3. **Обложка из файла:** ID3v2.2–2.4 (APIC/PIC), FLAC (PICTURE), M4A (covr).
   Достаётся при импорте; у уже загруженных файлов — при открытии библиотеки.
   Нет обложки — заглушка. Миниатюры видны в библиотеке.

**0.7.1 — вставки: видимые причины и плавный переход**

Симптом: при вероятности 100% вставка не срабатывала, и причина нигде не была видна.

1. **Строка `вставка: …` на плашке** и записи в диагностике на каждом шаге: когда будет
   жребий, что выпало, почему сгорело («следующий трек начался за N с до конца»,
   «нет файлов с галочкой», «интервал: ещё N мин», «длительность трека неизвестна»).
2. **Плавный переход между треками.** Если плеер запускает следующий трек за несколько
   секунд до конца текущего, раньше это считалось ручным переключением и вставка сгорала.
   Теперь старт следующего трека меньше чем за 12 с до конца — естественный конец,
   а хвост предыдущего трека глушится.
3. **Длительность из Media Session.** Если у потока плеера `duration` не число,
   длительность берётся из `navigator.mediaSession.setPositionState`.
4. **Запасной путь:** если следующий трек заиграл в обход `play()`, вставка всё равно
   перехватывает его на следующем тике.
5. **Кнопка «🎲 Вставить после трека»** в попапе: без жребия и интервала, для проверки.

**0.7.0 — вставки своих треков в «Мою волну»**

Состав волны формирует сервер, поэтому вставка делается на стыке треков, на стороне страницы.

1. **Жребий за 25 секунд до конца трека.** Фон проверяет интервал с прошлой вставки,
   бросает жребий с заданной вероятностью и выбирает случайный файл с пометкой «вставка»,
   не повторяя предыдущий. Файл заранее грузится в память.
2. **Следующий трек придерживается.** Когда трек доиграл и плеер вызывает `play()`
   для следующего, вызов поглощается: следующий трек стоит на 0:00, а вставка играет
   в собственном элементе. `src` плеера по-прежнему не трогается.
3. **Кнопки плеера управляют вставкой:** пауза и запуск (перехват `play()`/`pause()`
   с событиями для интерфейса плеера), перемотка ползунком, громкость.
   «Следующий»/«предыдущий» отменяют вставку.
4. **Только естественный конец трека.** Ручное переключение сжигает жребий.
5. **Кнопка `⏭ пропустить`** на плашке.
6. Настройки: включение, вероятность (по умолчанию 20%), интервал (по умолчанию 15 мин);
   галочка «Вставка» у файлов в библиотеке.
7. Исправлено: кнопка «Разорвать» в списке привязок удаляла привязку по несуществующему полю
   и ничего не делала.

**0.6.0 — параллельное воспроизведение вместо подмены `src`**

Симптом: привязанные треки переставали запускаться, остальные играли.
Причина найдена в захвате: Яндекс отдаёт зашифрованный поток
(`transport: "encraw"`, `/music-v2/crypt/`) и после расшифровки ставит элементу
свой `blob:`. Перехват сеттера `src` в 0.5.0 затирал любое присвоение — включая
blob самого плеера — и вступал с ним в бесконечную гонку.

1. **Сеттер `src` и `setAttribute` больше не перехватываются.** Тест проверяет
   это по коду и по поведению: `src` плеера после работы расширения не меняется.
2. **Своя копия в отдельном элементе**, плеер глушится, синхронизация 400 мс.
3. **Аварийный откат**: неподдерживаемый формат, ошибка декодирования, отказ
   `play()` — звук плеера возвращается, битая привязка отключается.
4. **Мост пересылает неизвестные типы сообщений** прозрачно — новая функция
   в странице больше не требует правки `bridge.js`.
5. В 0.5.0 плашка писала «играет локальная версия» сразу после подмены,
   не проверяя результат. Теперь успех объявляется, только когда копия реально играет.

**0.5.0 — подмена в отсоединённый элемент**

Диагноз по консоли: `document.querySelector('audio')` → `null`, `count: 0`,
`AudioContext` не создавался, но музыка играет и громкость регулируется.
Значит элемент создан через JS и не вставлен в DOM, а весь код 0.4.0 искал его
через `querySelector` и молча выходил — файл доезжал, подставлять было некуда.

1. **Реестр медиаэлементов** вместо поиска в DOM: перехват
   `Document.prototype.createElement`, `new window.Audio()`, `play()`, плюс
   резервный `scanDom` с обходом shadowRoot.
2. **`applyAll`** подставляет источник во все активные элементы реестра,
   а не в один найденный.
3. **Возвращён захват трафика**, потерянный в 0.3.0: перехват `fetch`/`XHR`
   снова пишет образцы в IndexedDB. Кнопка «Выгрузить захват» до этого всегда
   отдавала пустой массив — это была моя регрессия.
4. **`all_frames: true`** на случай, если плеер в iframe.
5. **Честный статус**, если элемент не найден: «плеер не найден (элементов: N)».

**0.4.0 — пустой артист и залипшая передача**

Причина по логу: `трек: определён « — Таблетка»`, артист пустой.

1. **`mediaSession || DOM` съедало артиста.** После логина Яндекс заполняет
   `mediaSession`, но без `artist`; короткое замыкание не давало добрать его
   из DOM. Ключ `|таблетка` вместо `мукка|таблетка`, скор 0.62 < 0.82.
   Теперь источники дополняют друг друга.
2. **Матч по одному названию** при отсутствии артиста: порог 0.90 и отрыв 0.12
   от второго кандидата.
3. **Передача файла больше не залипает:** таймаут шага, сброс через 20 с,
   перезапрос через 12 с, повтор чанка при обрыве.
4. **Ложное «оборвалось на»**: бралась первая ошибка, а не последняя запись.
5. **Прогресс загрузки** в плашке.

**0.3.0 — регресс определения трека**

`inject.js` стал зависимым от `window.YMU` с `return` при её отсутствии —
в 0.1.0 нормализация была внутри файла. Одна «дедупликация» выключила конвейер.
Нормализация перенесена в SW; страница получает готовый ответ.
Плюс: возврат к сетевому источнику при выключении, плашка статуса,
три пути определения трека, интеграционный тест.

**0.2.0** — единая нормализация, диагностика в попапе, запасной DOM-путь.

**0.1.0** — первая сборка: библиотека, автоматч, подмена через `blob:`.
